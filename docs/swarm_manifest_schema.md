# Garden Swarm Manifest & Configuration Schema

> **Normative Schema Specification for `garden-swarm.json` and `garden.toml`**  
> *A formal reference defining swarm topology, worker personas, opposing priorities, harness detection, and coordination bindings.*

---

## 1. Overview & Configuration Layering

Garden swarms are defined by two complementary configuration files in the repository root:

1. **`garden.toml`**: High-level project preferences, default harness target, workspace engine, and Two-Key gate test runner commands.
2. **`garden-swarm.json`**: The canonical runtime swarm manifest generated by `choose-personas` and consumed by `launch-workers` and `orchestrate-swarm`.

---

## 2. `garden-swarm.json` JSON Schema (Draft 2020-12)

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "GardenSwarmManifest",
  "type": "object",
  "required": [
    "version",
    "project",
    "harness",
    "orchestrator",
    "workers",
    "coordination"
  ],
  "properties": {
    "version": {
      "type": "string",
      "enum": ["1.0", "1.1"]
    },
    "project": {
      "type": "string",
      "description": "Canonical project name matching git repository slug."
    },
    "harness": {
      "type": "string",
      "enum": ["antigravity", "claude_code", "opencode", "codex", "pi", "cursor", "heterogeneous"],
      "description": "Target coding harness environment for swarm workers."
    },
    "orchestrator": {
      "type": "object",
      "required": ["name", "role"],
      "properties": {
        "name": { "type": "string" },
        "role": { "type": "string" },
        "inbox": { "type": "string" }
      }
    },
    "workers": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "required": [
          "name",
          "role",
          "tags",
          "model",
          "opposing_priorities",
          "inbox",
          "strand_prefix"
        ],
        "properties": {
          "name": {
            "type": "string",
            "description": "Unique, collision-free agent codename."
          },
          "role": {
            "type": "string",
            "description": "Specialized persona title (e.g. Systems Architect, Adversarial Auditor)."
          },
          "tags": {
            "type": "array",
            "items": { "type": "string" }
          },
          "model": {
            "type": "string",
            "default": "Session Default (active in window/tab)",
            "description": "Foundation model tier. Defaults to active session model."
          },
          "opposing_priorities": {
            "type": "array",
            "items": { "type": "string" },
            "description": "Dialectical tensions this worker must defend against other personas."
          },
          "inbox": {
            "type": "string",
            "description": "Redis inbox address."
          },
          "strand_prefix": {
            "type": "string",
            "description": "Directory prefix for worker's isolated Rift workspaces."
          }
        }
      }
    },
    "coordination": {
      "type": "object",
      "required": ["transport", "prefix", "tasks_queue"],
      "properties": {
        "transport": { "type": "string", "enum": ["redis", "valkey"] },
        "prefix": { "type": "string" },
        "tasks_queue": { "type": "string" },
        "multicast_channel": { "type": "string" }
      }
    }
  },
  "additionalProperties": false
}
```

[strands]

[gate]

allow_skip_gate = false

[coordination]
